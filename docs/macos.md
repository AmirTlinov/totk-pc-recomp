# Native Apple Silicon build

The macOS target executes prepared ARM64 game code with a direct Metal 4 renderer. It supports preparation for 1.4.3 (default) and 1.2.1. It requires Apple Silicon, macOS 26+, Xcode with its Metal toolchain, Python 3.14+, Ninja and .NET 10 for building the shader service. The packaged game needs neither Python nor .NET.

Full-game compatibility and 3840x2160 at 144 rendered frames per second are acceptance targets. A successful build or synthetic probe does not establish gameplay performance, physics correctness or driver stability. The pinned upstream renderer has previously recorded driver faults during full-game submission; game-data runs on the target Mac must resolve that boundary before declaring the port ready.

## Build

Install the tools and dependencies, then create the Python environment:

```sh
brew install ninja opus libvpx llvm dotnet openssl@3 brotli uv
uv venv --python 3.14 .venv-py314
uv pip install --python .venv-py314/bin/python -r tools/requirements-macos.txt
tools/fetch_refs.sh
```

Install Xcode's Metal Toolchain if `xcrun --find metal` fails. Static libraries must contain ARM64 and target macOS 26 or earlier. The builder checks their deployment targets and uses an installed compatible keg when the newest Homebrew bottle targets a newer OS.

Copy `config.macos.example.toml` to the ignored `config.local.toml`. Set paths to the base game, cumulative update, key file and firmware directory. Keys are passed by path. The native host requires verified system shared fonts, including for availability queries. Extraction and prepared game files stay under `build/` and `generated/`.

For a combined NSP, use the same path for `input.base` and its entry in `input.updates`. The importer selects the base and BKTR update independently and checks the resulting modules and RomFS against the supported version hashes. If the container omits its ticket, set `input.title_keys` to the matching encrypted `title.keys` or `title.keys_autogenerated` file. Title keys pass to hactool through stdin; normalized key files are never written.

```sh
.venv-py314/bin/python tools/build_game.py --target macos-arm64 --version v143 --extract --package
```

This extracts and verifies inputs, rewrites the ARM64 modules, runs structural/differential and native-call gates, creates runtime tables, prepares shaders and packages a locally signed app:

```text
build/macos-arm64/v143/TotK Recomp.app
```

When verified extraction already exists, use `--prepare-game --package` instead of `--extract --package`. Later builds can use `--package` alone. Use `--version v121` for 1.2.1. The builder uses the same pinned sources for both versions. Its source checkout in `refs/` remains untouched; changes are applied to an ignored export.

The host uses `-O3`, ThinLTO with an incremental linker cache, and dead stripping. Diagnostic entry points and probe objects are excluded from the game build. Source exports preserve timestamps only for unchanged bytes, so editing one patch does not rebuild unrelated objects. Static-library and compiler changes invalidate their consumers.

Shader preparation deduplicates identical MSL and reuses atomically published metallibs under a compiler/toolchain identity. These assets live outside the replaceable source export. An unchanged shader does not start the Metal compiler again. Temporary Cryptex installation paths are excluded from the compiler identity, so remounting the same Metal toolchain does not invalidate its libraries. Offline and runtime compilation both target Metal 3.2 with safe arithmetic. Precise multiply/add helpers use local contraction controls so the compiler can inline them without fusing separately rounded operations.

The signature is ad hoc for local use. Public distribution/notarization is a separate signing process. The playable app contains the player's game data and stays local.

`TotK Recomp Diagnostics.app` contains the real compiled host and renderer with explicit empty game tables. It refuses game boot. `--selftest` checks native execution and Metal 4 capability. The GPU runner tests masked clears, depth/stencil, resource aliasing/lifetimes, uniform snapshots, bindings and render-stream behavior under Metal validation; each run keeps separate logs. `--probe-warm-pipelines` compiles and executes 128 distinct render/compute pipelines and checks the critical-versus-bulk cancellation boundary; gameplay has zero warm-up compiler workers. The shader test uses a synthetic Maxwell kernel through the native translator, SPIRV-Cross and Apple's Metal compiler. It contains no game shader. The shader arithmetic test uses `glslangValidator` to generate precise SPIR-V operations and compares MSL 2.3 and 3.2 helpers on the GPU, including signed zero and separate-rounding controls. The attachment-ledger probe exercises all eight color targets plus depth and stencil.

The attachment-feedback probe reads pixels back after pending clears, barriers with intervening draws, storage aliases, nested texture views and MSAA copies. Writable images retain their original destination. The owner regression checks addressed closure, independent local phases, exact resource generations, dependent-cone invalidation and checkpoints. The command-owner regression exercises the production recorder and nested-copy lifetimes under ASan/UBSan. The GPU command-generation probe compares current argument buffers, vertex streams and texture bindings against direct rendering, including overlapping in-flight chunks and retirement of temporary state objects. The resolution test also compares both runtimes' allocation budgets against the RomFS heap generator, including diagnostic 4K runs.

## Rendering and measurement

The default profile fixes scene and output to 3840x2160, requests 144 Hz presentation, bounds the present queue to two tickets and disables MetalFX scaling/interpolation and experimental invisible-draw skipping. Runtime scaling/graphics toggles are locked. Required shader/pipeline failures stop strict rendering. The clock uses `CLOCK_UPTIME_RAW` without the upstream 120 Hz minimum-step clamp or per-call initialization and gate counters. Shader arithmetic keeps separate rounding; the native translator excludes Windows patch 0008 because it changes a support-buffer ABI the Metal host does not implement.

The game drives its anchor render loop at 48 Hz in the strict profile. `mtl_link_wait_tick` derives that three-tick stride from the 144 Hz Metal display clock instead of submitting full anchors that the present queue would coalesce. The two intervening ticks are available to retained phases. The display link presents the newest ready anchor and records every older coalesced ticket as dropped. The camera-only phase experiment is disabled by the strict profile. In diagnostic mode, `TOTK_PERIODIC_PHASE=1` allows a changed raw-mouse generation to publish a camera phase when no anchor is queued. With that experiment enabled, the replay boundary snapshots the final canvas before its first UI draw and anchor capture snapshots the same canvas after UI. Scene and anchor snapshots occupy immutable hazard-counted slots. A committed anchor publishes its index while the slot is still writer-owned and releases the slot afterwards; a writer revalidates the published index after its CAS, so a stale index snapshot cannot reclaim the new current anchor. A snapshot becomes visible only after its command buffer has entered the Metal queue and all newly registered allocations have been committed to the residency set; a discarded command buffer releases its unpublished slot. The phase rotates the pre-UI view rays using the G-buffer camera's field of view, composites changed UI pixels at their original coordinates, renders directly into the drawable in one 4K pass and receives its own presentation ticket and state generation. It does not advance simulation or complete an NVN ticket. Its three in-flight slots own their command allocators, command buffers, argument tables, render-pass descriptors and feedback options. The empty-queue phase path uses atomic queue snapshots, a preallocated display-clock semaphore and atomic allocator claims; it performs no heap allocation, mutex acquisition, residency commit or readback and skips instead of waiting when all slots are busy. The old MetalFX insertion path stays disabled. Parameterized ICB execution is opt-in until supported owner programs demonstrate an end-to-end gain.

The diagnostic phase renderer currently covers camera rotation and a pre-UI/post-UI canvas boundary. The changed-pixel mask has no explicit UI alpha, actors remain in the captured image, and newly exposed pixels have no retained-depth disocclusion repair. Its trace kind is `camera`; the benchmark excludes these presents from rendered-state Hz and rejects them for 4K/144 acceptance. Unique publication IDs alone do not establish unique correct world states. Retained depth, complete disocclusion geometry and authored actor/vegetation/particle laws are still required. The separate UI replay described below has not yet been connected to a world-phase renderer. The current 48-Hz anchor cadence therefore cannot provide 144 correct states per second.

`periodic_ui.m` captures ordered UI draws and their resolved inputs before render-stream packetization. `TOTK_PERIODIC_UI=1` enables its integration on the native renderer. Each capture owns immutable uniform, vertex and index data, sampled texture copies, shader constant allocations and render state. Writes invalidate only captures whose texture storage overlaps; unsupported bindings reject the capture. A GPU comparison composites the captured draws over the original pre-UI scene and compares every pixel with the original canvas. Only an exact match can publish that frame and canvas owner for later composition. GPU feedback owns resource retirement, and an older completion cannot replace a newer publication. This capture/reference path adds work and stays off by default. It supplies stable UI coordinates; it does not certify a temporal world state or bypass guest scene work.

The render stream publishes render-pass begin, draws and end directly to the encode FIFO. It does not buffer a whole pass, hash dynamic packets or run a pass-memoization learner. This preserves overlap between replay and Metal encoding. Unproven output retention never skips a render pass.

`periodic_owner.c` implements the addressed control model separately from Metal. An immutable program owns explicit phase transitions and the port obligations of each action. A participation owns its causal entry, local phase, bindings and invocation receipts. A return must match that participation, incarnation, role, phase, parameter generation and resource versions. External contact revokes open receipts and traverses only reverse dependency links. Completion advances the owner's explicit action; submission order and anchor publication do not advance it. Program and dependency allocation happens on the serialized control path; begin/return/complete and invalidation allocate nothing. Checkpoints preserve a partial course and require the caller to restore the matching external parameter data. This domain module does not yet identify game actors or certify GPU output retention.

`periodic_gpu_encode.m` compiles one immutable Metal program that creates indirect draw commands from current parameter rows. The renderer captures these rows before creating ordinary render-stream packets. Pipeline, buffers, draw arguments and raster state are parameters; changing them does not compile another program. Viewport, scissor, stencil reference, blend color and visibility changes delimit ordered ICB ranges. Each command buffer owns its rows, ICB, residency set and state references until its own GPU feedback. One compute dispatch generates the commands before their render passes; its count is finalized before commit. Unsupported draws use the ordinary path with complete explicit state restored. Storage grows on a cold worker when needed, without waiting in the draw path. `TOTK_PERIODIC_GPU_ENCODE=1` enables this path for profiling. The recorder carries compatible draw spans into replay. The GPU generator is not started for fewer than 1024 remaining draws, spans with fewer than 16 draws per external state change, deferred bindings, or smaller configured chunk budgets. These conservative thresholds come from the local direct-versus-generated command measurements; they are not an end-to-end gameplay speedup. The normal 75-draw chunk policy therefore uses direct encoding without allocating parameter rows or starting command generation. Draw command generation alone does not establish temporal closure or reduce the number of guest draws.

Recorded NVN command copies also have an explicit owner incarnation and immutable child-scope metadata. `CallCommands` retains its child until finalization and copies the body directly into the final flat command allocation. Deferred lists and `CopyCommands` retain their original immediate-copy semantics. Texture pins and child lineage survive source retirement until every owning parent releases them. This removes an intermediate body copy; recorder ownership does not identify scene actors or establish their temporal laws.

For 1.2.1, `TOTK_PERIODIC_SCENE=1` connects the render-object dispatcher, collection calls and base destructor to `native_scene.c`. Each draw invocation carries its actual object, lifetime generation, virtual implementation and role into the NVN recorder. Nested command calls preserve that address; deferred draws and cube groups preserve it with their draw state. A recording without scene work bypasses scene lookup. This adapter supplies scene identity only: it does not retain geometry, establish a temporal action or replace GPU execution. It stays off by default until the scene executor consumes these invocations.

`periodic_clock.c` separates completed simulation time, the next guest timestep, anchor publication and requested presentation time. The guest callback is `runtime_simulation_step_update`; the async presentation job carries its immutable stamp. The initial step matches the configured anchor cadence. Subsequent steps use active elapsed time without a five-sample average; intervals beyond the maximum guest step retain debt instead of disappearing. Lifecycle suspension and the explicit first-world shader warm-up wait are excluded. Independent suspension reasons compose without resuming a still-suspended clock. A display-phase query is read-only and cannot advance guest logic. The 1.4.3 guest half-step selector remains authoritative; the host timestamp alone does not establish every subsystem's temporal state.

Replay jobs and their present job carry the same producer-assigned frame identity. Scene validation and camera lookup require that exact frame; a previous frame cannot satisfy an anchor.

The resolution patches disable the game's dynamic scene multiplier, including 1.2.1's emergency reduction, while preserving each effect's downsample ratio. Original instructions are checked before any write. Scene validation applies to full-canvas composition; smaller inventory and effect targets do not establish the presented scene's dimensions. With local 1.2.1 modules, `python tests/macos_resolution_test.py` executes both size producers against Unicorn.

Frame execution and command replay use user-interactive QoS. They keep the system's normal scheduling policy: loading and guest-worker waits make their work unsuitable for a fixed real-time CPU budget. The policy probe checks both frame threads without requiring game files. See Apple's [CPU scheduling guidance for games](https://developer.apple.com/videos/play/tech-talks/110147/) for QoS propagation and the limits of fixed-priority work.

Guest yields first hand their virtual core to an eligible game thread. With no eligible peer, they use an ARM execution hint: Darwin's `sched_yield` can delay the caller behind unrelated host work. Yield without migration retains its core; yield-to-any also admits lower-priority peers. Actual waits still release the virtual core and block. The thread test checks empty yields, peer priorities, affinity changes during wake-up, timed sleeps and optional polling backoff under AddressSanitizer and UndefinedBehaviorSanitizer.

Repeated argument addresses, exact pool lookups and uniform snapshot lookups use validated caches. GPU probes compare cached results with the authoritative path, including invalidation and encoder changes. The idle GPU spin-kernel thread defaults off. Recorded startup pipelines warm before play. If an unrecorded pipeline still appears, the native profile predicts only the remaining draws of the current render pass, whose attachment formats are already exact, and compiles at most eight missing pipelines in parallel. Cross-pass prediction stays off because its depth/stencil guesses compiled mostly unused states. `TOTK_GPU_KEEPALIVE`, `TOTK_PSO_PREDICT`, `TOTK_PSO_PREDICT_CROSS_PASS`, `TOTK_ARG_BIND_CACHE`, `TOTK_POOL_QUERY_CACHE` and `TOTK_USNAP_INDEX` remain explicit environment controls for profiling; a microbenchmark win does not establish a gameplay win.

Render-pass barriers track attachment and reflected image writes by texture serial. An independent following vertex stage may overlap earlier fragment work. A vertex texture dependency, reused attachment, writable storage buffer, unresolved image write or utility render pass promotes the boundary back to a full barrier. `TOTK_BARRIER_NARROW=2` bypasses those dependency checks and remains a diagnostic negative control; the strict profile uses checked mode 1.

`TOTK_NATIVE_4K144=0` enables upstream diagnostic behavior. Such a run cannot satisfy strict acceptance.

Recorded pipeline warm-up compiles independent Metal states in bounded batches, keeping manifest priority. Descriptors and shader variants remain owned by one thread. `TOTK_WARM_THREADS` controls both library and pipeline workers (default up to eight). The exact recorded working set finishes behind the first-world loading screen; the broad translated-shader sweep is cancelled and joined before play, so Metal compiler workers cannot contend with a live frame. New pipelines still compile before the draw that needs them; missing draws are never used to hide compilation delays.

The native shader chain asks SPIRV-Cross to zero-initialize temporary variables and treats Metal's `sometimes-uninitialized` diagnostic as a build error. This keeps conditionally written shader outputs deterministic instead of leaking undefined register values into foliage, particles or other sparse geometry.

The local package keeps `TotK Recomp.app` and `TotK Recomp Data` beside each other. The signed app contains code, overlays and prepared shaders; the 16 GB read-only RomFS stays in the sibling data directory so code signing and every native launch do not hash the game image. Move the app and data directory together.

Capture actual drawable presentation timestamps by launching the app executable from a terminal:

```sh
TOTK_FRAME_TRACE="$PWD/build/gameplay.csv" \
  'build/macos-arm64/v143/TotK Recomp.app/Contents/MacOS/TotKRecomp'
PYTHONPATH=tools .venv-py314/bin/python -m macos.benchmark build/gameplay.csv \
  --start-ticket 1000 --end-ticket 11000 --output build/gameplay-result.json
```

Select the measured gameplay segment explicitly; the analyzer reports excluded frames. Keep cold-start/shader preparation and steady gameplay captures separate. A gameplay segment must last at least 60 seconds. Rows carry frame kind, source anchor identity, publication generation, scene/output/drawable dimensions and presentation ticket. The immutable clock fields record completed simulation generation/time/step, requested display-phase time and requested presentation time. FIFO presentation has no exact deadline and records an unknown target as zero. A display phase cannot claim a completed guest step. Anchors use phase 1 as their row marker; diagnostic phases use the elapsed fraction after their source anchor.

The analyzer reports simulation, anchor, rendered-state and presentation rates separately. Gaps in simulation generations expose coalesced anchors even when actual presentation tickets remain consecutive. Camera reprojection and unverified phase labels never increase rendered-state Hz. State IDs prove publication order only. Unknown dimensions/timing, repeated or reordered states and dropped tickets fail the numeric check. Simulation time must track both actual and requested presentation time throughout the capture. Its fixed endpoint/debt allowance is reported separately and cannot grow with capture length or an oversized guest step. Rendered-state rate must reach 144 and p99 must fit 6.944444 ms; cadence tolerance covers only timestamp quantization and floating point precision, reported in nanoseconds.

An explicit `TOTK_INPUT_FILE` accepts read-only `flag pass_gpu N` (up to 120 frames), `flag draw_log N` and `flag uw_log N` captures without unlocking graphics settings. `TOTK_PASS_GPU_FILE` selects a TSV for per-pass GPU timestamps. Exclude those instrumented frames from performance acceptance; pass timing changes submission boundaries.

Presentation callbacks enqueue immutable records; a dedicated writer formats and buffers CSV. It flushes at least once per second while active, and normal window close drains the queue. An abrupt process failure may lose the tail. Queue overflow or I/O failure stops the capture instead of silently dropping records. With tracing disabled the present path does not capture frame metadata.

These timing and dimension checks still need visual acceptance at a physical 4K/144 display mode: fixed allocation dimensions alone do not prove viewport coverage or image fidelity. Check the same saves/routes for terrain, transparencies, shadows, UI, physics, cloth, input latency and audio. Dynamic resolution, MetalFX interpolation and reused frames cannot count toward the target. A phase counts only when the native renderer publishes a distinct retained state and passes the same-resolution reference comparison for its exact simulation time and display phase. No target result is inferred from GPU probes or from another machine.

Use View > Enter Full Screen (Control-Command-F) for fullscreen presentation. The diagnostic input stream accepts `fullscreen 0|1` through the same window transition. Windowed composition can discard submitted drawables; only actual presentation timestamps count.

Click the game picture to capture the mouse; the capture click performs no game action. Escape goes back and releases it. Switching applications, minimising, resizing, changing fullscreen mode or opening text entry also releases it. Click again to resume. The 1.2.1 normal camera consumes mouse displacement directly, without the analog stick's dead zone, speed limit or frame-time multiplier. It retains the game's collision correction and pitch limits. Targeting, aiming and quick menus retain their right-stick input path. A stopped normal camera releases mouse movement to the menu; each delta is consumed once. The mouse uses GameController device deltas where available and AppKit relative events otherwise. 1.4.3 currently uses the analog mouse path; its direct-camera and font-cache adapters need separate version validation.

Prompt labels come from the same bindings as input. Keyboard or mouse use selects PC glyphs; controller use selects Xbox, PlayStation, Switch or generic controller glyphs. Disconnecting the last controller returns to PC prompts. Physical controller assignments from `controls.txt` are reflected in the labels. Existing cached font glyphs refresh when the active device changes, and bitmap prompts use immutable, cached Metal variants. The controller reference diagram uses the same mapping. Font-cache replacement is currently validated for 1.2.1.

`TOTK_MOUSE_SENS` sets initial sensitivity (0 to 10, default 1; zero disables capture), and `TOTK_MOUSE_INVERT_Y=1` reverses vertical camera input. The diagnostic input stream accepts `capture 0|1`, `mouse <dx> <dy>` (positive Y is up), `mousebutton <0..4> <0|1>` and `prompts <0..4>` (keyboard, Xbox, PlayStation, Switch, generic). Mouse buttons are left, right, middle, back and forward. These commands are disabled unless `TOTK_INPUT_FILE` is explicitly configured.

`tests/macos_mouse_test.py` checks delta ownership, frame-rate independence, brief clicks and focus changes. `tests/macos_game_input_test.py` checks hook installation, camera direction and protected modes. `tests/macos_prompts_test.py` checks actual bindings, device families and atlas replacement, including allocation failures; `tests/macos_prompt_assets_test.py` checks archive bounds and isolated layout changes. The C checks use AddressSanitizer and UndefinedBehaviorSanitizer.

## Player files and saves

| Data | Location |
|---|---|
| Versioned profiles | `~/Library/Application Support/TotKRecomp/<version>/` |
| Shader cache | `~/Library/Caches/TotKRecomp/<version>/<toolchain-OS-GPU identity>/` |
| Logs | `~/Library/Logs/TotKRecomp/` |

Fixed `TOTK_SHADER_CACHE` development overrides also receive the toolchain/OS/GPU namespace. Changing translator settings requires rebuilding the native toolchain; alternate Python/DLL/debug translators cannot reuse its cache.

Only one local app instance can own the player profile. A save writes to `save-tx/work`. Commit snapshots it with APFS copy-on-write, calls `fsync` on the files, atomically exchanges the committed directory, flushes publication metadata and completes one checked `F_FULLFSYNC` drive barrier before returning success. This barrier also persists every preceding file sync on the device. Failures return to the game and retain working data. Last writable-mount unmount rolls back to the committed generation; dirty work is kept in a recovery directory. Read-only mounts cannot modify either generation. Clean restarts do not accumulate recovery copies.

RomFS streaming has a separate handle-lifetime lock. Save publication cannot block asset reads, and closing an overlay file waits for its readers before releasing the descriptor.

The previous committed generation and interrupted recovery work remain under the profile. Recovery copies are deliberate player data; they are never silently pruned. Fault-injection tests cover copy/flush/publication failures and process termination. They do not simulate physically removing power from the storage device.
